# M1 — Telegram login and the first text column

Requested on October 5 after the working M0 demo. Implement the setup/login
flow and let the owner select one chat once authenticated.

1. Pin `tdl` and `prebuilt-tdlib`; use the types bundled with the pinned binary.
2. Add private atomic config/layout storage outside the repo. Save API details
   and a random database encryption key with mode 0600. Set the process umask
   before TDLib creates its database, and give its directories mode 0700.
3. Use manual TDLib auth state handling: API setup, phone, Telegram/SMS/other
   code, two-step password and optional email steps. Reject registration and
   unsupported purchase/device confirmation states explicitly. Restore sessions
   on restart and allow API corrections before login finishes.
4. Disable TDLib log output and tdl debug output. Never echo credentials, auth
   challenges, password hints, account names or raw errors in logs/responses.
   Add bounded JSON bodies, exact payload validation, auth-step checks, a
   single in-flight auth operation and server-enforced flood-wait cooldowns.
5. After auth, expose an explicit chat picker. Load up to 50 messages in one
   selected chat, persist only its ID privately and receive live new/edit/delete
   updates. Exclude secret chats. Do not call viewMessages/mark-as-read APIs.
6. Reuse the existing loopback, Host, cookie, Origin and CSP checks. Keep demo
   mode isolated; no Telegram setup/auth routes exist there.
7. Test with an injected synthetic TDLib transport: state changes, retry/error
   redaction, persistence, input limits, endpoint access, flood waits and chat
   history. Check the native library loads without providing credentials or
   contacting Telegram. Verify UI using synthetic auth screens and the empty
   real setup screen only.
8. Update docs, scan, commit and push privately. Start live mode for the owner
   and leave the browser at API setup. The owner enters every real credential
   locally. Do not inspect or screenshot the browser after real auth starts.

## Limits

- This milestone reads text/captions and displays placeholders for media.
- One chat column can be selected/replaced. Full column editing arrives in M2.
- Message formatting, sending and media streaming remain later milestones.
- Real-account verification is performed by the owner after the handoff.
- Phone/code/password/email inputs are forwarded to TDLib, never persisted by
  tgdeck. TDLib maintains its own private session/database as required.
